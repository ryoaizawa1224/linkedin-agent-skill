# li-post

1つの素材から、本人が書いたように見えるLinkedIn投稿を作るSkill。

## 書く前に

1. `~/.codex/linkedin/voice.md` があれば読む。これは文体、使わない言葉、想定読者などを記録したプロフィール。存在しない場合は、本人の過去投稿を3本もらい、そこから文体を推定して作る。文体を勝手に捏造しない。
2. このフォルダの `hooks.json` を読む。21種類のフック、テンプレート、例、向いている用途、失敗パターンが入っている。
3. 「AIについて投稿して」のように素材が薄い場合は水増ししない。何が起きたか、誰に起きたか、どんなコスト／成果があったかをまとめて確認する。投稿には最低1つ、具体的で真実な事実が必要。

## 投稿の形

```text
1行目      フック。単独で成立させる。
2行目      1行目への答え・続き。単なる前置きにしない。
本文        1〜3行程度の短い段落。段落間は空行。
転換        それまでの見方を1行で反転・整理する。
締め        具体的な質問か具体的な行動指示を1つだけ。
```

## 作成フロー

1. `hooks.json` から本当に合うフックを3種類選ぶ。同じ型の言い換え3案にはしない。
2. 最も強いフックで本文を書く。
3. `$li-human` を使い、定型表現や機械的な特徴をチェック・修正する。
4. コピペ可能な投稿本文を出し、使用したフック、文字数、humanizer結果などを併記する。
5. **自動公開しない。** ユーザーが投稿する。ユーザーが承認した場合のみ、日付、使用フック、1行目を `~/.codex/linkedin/log.md` に追記し、後の `$li-audit` で使えるようにする。

## ルール

- 1投稿1テーマ。2テーマあるなら2投稿に分ける。
- 形容詞より具体的な数値を優先する。
- 「Thoughts?」「Agree?」のような汎用engagement baitを避ける。
- ハッシュタグは最大3つ。実際に意味のあるカテゴリだけ。
- 実績、売上、顧客、成果などを捏造しない。不明な数字は `{{あなたの数字}}` として未確定であることを明示する。

## 呼び出し例

```text
$li-post 社内ツールで提案書作成が5時間から20分になった話
```
